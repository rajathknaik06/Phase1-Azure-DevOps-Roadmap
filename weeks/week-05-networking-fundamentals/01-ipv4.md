# Week 5, Lesson 1: IPv4

> **Week 5 - Networking Fundamentals** - Topic 1 of 7 | Shell used: Windows PowerShell **and/or** Linux shell, as labelled on each command

Week 5 explains how computers find each other.

## 1. Explanation from scratch

An **IPv4 address** identifies a device on a network. It is a **32-bit** number written as four **octets** (8 bits each) separated by dots, e.g. `192.168.1.25`. Each octet ranges 0-255 because 8 bits give 2^8 = 256 values.

An address has two parts: a **network portion** (which network) and a **host portion** (which device on it). The subnet mask or CIDR prefix (next lessons) says where the split is.

**Private ranges** (not routable on the public internet): `10.0.0.0-10.255.255.255`, `172.16.0.0-172.31.255.255`, `192.168.0.0-192.168.255.255`. Home routers use `192.168.x.x`. `127.0.0.1` is **localhost** (your own machine).

Binary example: `192` = `11000000`, `168` = `10101000`, so `192.168.1.25` = `11000000.10101000.00000001.00011001`.

## 2. Simple analogy

An IP address is a **postal address**: the street name is the network, the house number is the host.

## 3. Key terms

- **Octet** - 8-bit group (0-255).
- **Network portion** - Identifies the network.
- **Host portion** - Identifies the device.
- **Private IP** - Reserved internal range.
- **Localhost** - `127.0.0.1`, this computer.

## 4. Examples and commands

Windows PowerShell:

```powershell
ipconfig
```

Look for `IPv4 Address . . . : 192.168.1.25`.

Linux / WSL:

```bash
ip addr
```

Look for a line `inet 192.168.1.25/24`.

Python-free binary check in PowerShell:

```powershell
[Convert]::ToString(192,2).PadLeft(8,'0')   # 11000000
```

## 5. Step-by-step instructions

1. Run `ipconfig` (Windows) or `ip addr` (Linux) and write down your IPv4 address.
2. Decide whether it is private using the ranges above.
3. Convert the first octet to binary.
4. Ping localhost: `ping 127.0.0.1` (PowerShell) or `ping -c 3 127.0.0.1` (Linux).

## 6. Hands-on exercise

Is `172.20.5.9` private? Is `8.8.8.8`? Convert `10.0.0.1` to binary.

## 7. Worked solution

`172.20.5.9` is private (inside 172.16-172.31). `8.8.8.8` is public. `10.0.0.1` = `00001010.00000000.00000000.00000001`.

## 8. Common mistakes

1. **Octet over 255** - `256.1.1.1` is invalid.
2. **Thinking `192.168.x.x` is reachable from the internet** - It is private.
3. **Running `ipconfig` on Linux** - Use `ip addr`.

## 9. Revision notes

- 32 bits, four octets 0-255.
- Network + host portions.
- Private ranges; `127.0.0.1` = localhost.
